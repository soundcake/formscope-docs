Permissions

Every table, chart, gadget, drill-down and export shows only data the viewer is allowed to see.

Request access

Each time a report runs, FormScope asks Jira, as the viewer, which of the indexed requests they can browse. Project permissions, issue security levels and recent permission changes all apply. Totals, chart labels, filter choices and exports are computed only from those requests.

Form view restrictions

Native forms can restrict who can view a form, separately from who can view the request.

  • FormScope reads forms with its own app identity. Jira refuses FormScope access to forms with view restrictions, so their answers are not indexed at all. FormScope marks the data source as having restricted forms.
  • By default, FormScope also checks each viewer's access to each form with Jira before using its answers. If you add FormScope to a form's restriction list, this check keeps those answers limited to people allowed to open the form. The check is always on for data sources where restricted forms were detected.
  • Access checks are cached for each viewer for up to two hours. Removing someone from a group used in a form restriction can therefore take up to two hours to reflect in FormScope.

App access and admin powers

  • Jira admins choose forms, questions and mappings. They don't get extra data access in reports: reports always apply the viewer's own Jira permissions.
  • Admins can limit who can use FormScope to chosen groups.
  • Report names and settings are visible only to people who can see the report. Admins see only how many reports each person owns.

What FormScope never does

  • It never copies answers into Jira fields or issue properties.
  • It never sends form data outside Atlassian's platform.
  • It never trusts user identity or permissions sent from the browser; it uses Atlassian's signed context.
